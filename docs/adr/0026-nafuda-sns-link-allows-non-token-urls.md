# ADR-0026: SNSリンクの nafuda.me 拒否をトークン付きURLに限定し、トップ・紹介ページ・サブドメインを許可する

- **ステータス**: 採用
- **決定日**: 2026-07-26

## 背景

ADR-0015 は、他人のなふだのプロフィールURL（`/u/{urlId}/p/{token}`）を SNSリンクに貼ると本人の同意なく [[ShareToken]] を公開してしまう露出経路を塞ぐため、SNSリンクのURL検証で **`nafuda.me` およびサブドメインのあらゆるURLを拒否**することにした。理由は (1) ShareToken 露出の防止と、(2)「SNSリンク＝外部サービス」というグロッサリー定義の維持、の2点だった。

その後、開発者側の実需要として「自分の SNSリンク欄に nafuda.me のトップページ（サービス紹介）や、別サブドメイン（例 `asatomo.nafuda.me`）を貼りたい」という要望が出た。これらのURLには秘密トークンが含まれず、貼っても誰の ShareToken も露出しない。ADR-0015 の広い拒否は、露出リスクの無いURLまで巻き込んで拒否しており、実害の無い自己紹介導線を妨げていた。

## 決定

**SNSリンクの nafuda.me 拒否を「秘密トークンを含む公開パス」に限定する。** トークンを含まない `nafuda.me` / `*.nafuda.me` のURLは許可する。

拒否対象は、パスが以下のいずれかにマッチする nafuda ホスト（`nafuda.me` または `*.nafuda.me`）のURLのみ:

- `/u/{urlId}/p/{token}` — 見せる（プロフィール）
- `/connect/{token}` — つながる
- `/favorites/add/{token}` — お気に入り追加

上記以外（トップ `nafuda.me`、`nafuda.me/terms` などの通常ページ、`asatomo.nafuda.me` などのサブドメイン）は許可する。実装は `src/server/functions/profile.ts` の `isNafudaTokenUrl()`。従来の `isNafudaHost()`（ホスト一致のみで拒否）を置き換えた。クライアント側（`profile/edit.tsx`）はサーバーの throw メッセージをそのまま表示する構造のため変更不要。

自分の別のなふだへの内部導線は引き続き「なふだリンク」（ADR-0015 の `nafuda_links` / `targetPersonaId` 内部参照）に一本化する。この ADR はあくまで **外部紹介としての非トークンURL** を許可するもので、なふだ→なふだの参照方法は変えない。

## 却下した代替案

- **すべての nafuda.me URL を許可**: 開発者要望（トップ・サブドメイン）は満たすが、ADR-0015 が塞いだ ShareToken 露出経路（他人の `/u/../p/{token}` を貼れてしまう）を再び開けてしまうため却下。トークン付きパスの拒否は維持する。
- **トップページ（ルートパス）だけ許可**: 最小の緩和だが、`asatomo.nafuda.me` などサブドメイン紹介ページや `nafuda.me/terms` を許可できず、要望を満たさない。露出リスクはパスの有無ではなくトークンの有無で決まるため、判定軸をトークンに揃えるほうが一貫する。

## トレードオフ

- **失うもの**: 「SNSリンク＝完全に外部サービスのみ」という単純な線引き。自社ドメインでも非トークンURLは載るようになる。
- **得るもの**: サービス紹介・サブドメイン導線の自由、露出リスクの有無（トークンの有無）に判定軸をそろえた一貫性。ShareToken 露出防止という ADR-0015 の実質的な安全目標は維持される。
- **許容できる理由**: ADR-0015 の核心はトークン露出の防止であり、それはトークン付きパスの拒否を続けることで保たれる。「外部サービスのみ」という概念上の純度は、実害の無いURLまで拒否するコストに見合わない。
