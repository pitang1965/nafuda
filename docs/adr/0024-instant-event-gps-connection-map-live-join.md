# ADR-0024: 即時イベントGPSをコネクション地図として公開し、座標はライブJOINで持つ

- **ステータス**: 採用
- **決定日**: 2026-07-04

## 背景

即時イベント作成時（「なふだを交換する」→「今どこで？」）に発行者Aの端末からGPS座標を取得し `events.gpsCoordinates` に保存している（CONTEXT.md コネクション②）。しかしこの座標は**現状どのUIにも表示されていない**。読み出しているのは `getActiveCheckin`（どこからも呼ばれないデッドコード）と `getEventParticipants`（認証不要の公開関数が `event: eventRow[0]` で全カラム返却しており、shareToken を知る第三者にAの座標が漏れる既知リーク）だけで、実質「書き込むだけの潜在データ＋公開リーク1件」だった。

2026-07-04 に通常イベント作成時のGPS取得を廃止し既存データをクリアして、GPSを即時イベント専用に絞ったばかりである。その直後に「即時GPSに初めての正当な用途——コネクション一覧から〈会った場所〉をGoogle Mapで開く——を与えるか、用途がないならGPSごと廃止するか」の岐路に立った。

当初の認識は「各コネクションに座標が入っている」だったが、実際には `connections` テーブルに座標カラムは存在せず、座標は `events` 側にのみある。A→B と B→A の両行は**同一の `eventId`** を指すため、解決される座標は常に**「A（QRを見せた側）のその場の1点」**であり、コネクションごとに固有でも対称でもない。

## 決定

即時GPSを廃止せず、**コネクション一覧の地図導線として初めて正当に使う**。あわせて同じ座標の裏口を塞ぐ。

1. **地図導線**: コネクション一覧に、即時イベント由来で座標を持つ行だけ「地図で開く」可視アイコン（ピン）を出す。Google Maps URL は公式 Maps URLs API 準拠で `https://www.google.com/maps/search/?api=1&query=<緯度>,<経度>`（座標は `{x:経度, y:緯度}` なので `query=${y},${x}`）、新規タブ＋`rel="noopener noreferrer"`。両行が同じイベント座標を解決するため、**Aは自分の位置を、BはAのmeet位置を見る**（非対称な露出）。アイコンはプロフィールへの `<Link>` の外に置く（`<a>` 入れ子回避）。
2. **保持方式はライブJOIN**: 座標を `connections` にスナップショットせず、`getMyConnections` の既存 `events` LEFT JOIN に `gpsCoordinates` を1カラム足して都度取得する。スキーマ変更・マイグレーション不要。これは ADR-0012（即時イベント文脈のスナップショット）の**意図的な例外**であり、ADR-0004（コネクション表示はライブJOIN）の路線に沿う。
3. **リーク解消をセットにする**: `getEventParticipants`・`checkinToEvent` の全カラム返しを明示カラム選択に変え `gpsCoordinates` を落とす。デッドコード `getActiveCheckin` を削除する。

## 却下した代替案

- **即時GPSごと廃止（記録停止＋カラムクリア）**: 2026-07-04 の通常GPS廃止と一貫し、リーク面も消える。しかし「会った場所を地図で残す」というユーザー価値を捨てる。露出先が「実際に会ってつながった相手」に限られ、内容が「共有した会場」であること、Aに記録前の拒否手段（GPS拒否・スキップ）があることから、廃止せず正当用途を与える方を採る。
- **座標をコネクションにスナップショット（ADR-0012 準拠）**: 機微データのコピーが2テーブルに増え、消し込み・監査対象が広がる。将来また即時GPSを廃止する際に `connections` 側に残骸が残る。単一ソース（`events`）へ集約する方がプライバシー的に優れる。
- **場所名（`venueName`）での地図検索（機能A）**: 全コネクションで動くが精度がフリーテキスト依存で、「正確な地点を残したい」という意図に合わない。
- **リークを機能と切り離して後回し**: 同じ座標を正当に地図表示しながら、匿名の第三者に漏らし続けるのは筋が通らない。機能とセットで塞ぐ。

## トレードオフ

- **失うもの**: 即時イベント行が削除されると（`eventId` → null）ピンも消える（座標をコネクションに保持しないため。ただし `eventName`/`venueName` も同時に消えるので「文脈が丸ごと消えたら地図も消える」で一貫）。Bに A の meet 位置が恒久的に見える（Aが自宅で即時イベントを作った場合は自宅ピンが残りうる）。2026-07-04 のGPS縮小方向を部分的に反転させる。
- **得るもの**: 「会った場所」をワンタップで地図表示。座標は単一ソースで、将来の一括クリアが1箇所で済む。マイグレーション不要（JOIN 1カラム）。長年放置の公開リークの解消。
- **許容できる理由**: 露出は対面でQR交換してつながった当事者間に限られ、内容は共有の会場。Aは記録前にGPSを拒否・スキップでき、自宅など見せたくない場所では切れる。precision 懸念はA側の同意と拒否手段でコントロールされ、本当のリスクである匿名第三者への漏洩は本ADRの決定③で解消する。
