# ADR-0025: 出会いの夜空は出会いの客観属性のみを符号化する（平等原則）

- **ステータス**: 採用
- **決定日**: 2026-07-06
- **関連**: ADR-0007（関係強度・フォロー概念の却下）、ADR-0021（お気に入り＝私的ブックマーク、社会的フォロー再却下）、ADR-0018（ボトムナビ4タブ構成）、ADR-0024（即時イベントGPSの単一ソース管理）

## 背景

lit.link / Linktree 系との差別化として「アート的な新しい体験」を検討した結果、競合が構造的に持てない資産——**時間と場所を持つ出会いのグラフ（[[コネクション]]）**——を素材に、オーナーだけが眺める作品ビュー「[[出会いの夜空]] (MeetingSky)」を導入することにした。各コネクション＝1つの星、同一企画イベント由来の束なり＝星座、として夜空を描く。

このとき避けて通れないのが「**星の見た目の差異（明るさ・大きさ・色）に何を語らせるか**」という符号化の設計判断である。ここには過去に却下した概念を視覚の裏口から再導入するリスクが潜む。

## 問題

星の視覚差異に割り当てうる候補と、その帰結：

| 候補 | 帰結 |
|---|---|
| ① 出会いの客観属性（時期・季節・時間帯・イベントの束なり） | 決定的（同じデータ→同じ空）。評価軸なし |
| ② オーナーの関与量（メモを書いた・見返した・地図を開いた） | 「書かないと暗い星＝冗長な出会い」という意図しない価値序列。関係強度の視覚的再導入 |
| ③ 相手のなふだ由来の色（スタイル・アバター主色） | ライブ参照のため相手のスタイル変更で自分の夜空が勝手に変わり、「あの日の記憶」という不変性と矛盾 |

②は ADR-0007 が却下した関係強度、ADR-0021 が再却下した「見せ合い・育て合い」の構造を、数値ではなく輝きとして持ち込むものである。エンゲージメント施策として将来必ず誘惑が来る経路であり、明示的に塞いでおく必要がある。

## 決定

**出会いの夜空は、出会いそのものの客観属性のみを符号化する。どの出会いも等しく一つの星であり、関係の強弱・頻度・関与量など評価的な軸は一切持ち込まない。**

- **位置＝時期**：全コネクションが必ず持つ `createdAt` を普遍軸とする。GPS・会場名など疎なデータを主役にしない（データの薄いユーザーでも空が破綻しない）。
- **星座＝同一企画イベントの束なり**：`eventId` を共有するコネクション群を線で結ぶ。即時イベントは交換ごとに独立（束ねない設計。CONTEXT.md [[イベント]]）なので星座を作らない。
- **オーナー専用**：夜空はオーナーだけが見る（公開プロフィール非掲載）。つながりタブ内のビュー切替（リスト／夜空）として住まわせ、新タブは増やさない（ADR-0018 の4タブ構成を維持）。
- **書き出し境界**：外部に出る唯一の経路は任意のPNG書き出しで、**星・星座線・期間表記のみ**を含む。相手の名前・イベント名・地名・位置を示唆する情報は一切含めない（相手の同意問題・即時イベント名＝私的ラベルの漏洩・位置推定をすべて構造的に回避）。
- **消える星**：相手のなふだ削除・退会でコネクション行が消えれば星も消え、跡は残さない（削除カスケードの既存方針に従う。消えた相手の痕跡を保持しない）。

## 却下した代替案

- **関与で輝きが育つ星（②）**：育成の情緒はあるが、関係強度の視覚的再導入であり ADR-0007/0021 と矛盾。却下。
- **相手のなふだ由来の色（③）**：記憶の不変性と矛盾し、相手都合で自分の作品が変わる。却下。
- **公開プロフィールへの掲載**：匿名化しても「出会いの多寡」というソーシャル比較を生み、ADR-0021 が却下し続けたフォロワー数的な見せ合い構造を裏口から入れる。却下。
- **企画イベント名入りの書き出し**：イベント自体は公開事実だが、「この日この会に居た」という行動履歴の公開になり、同じ星座にいる他参加者の存在も間接的に示唆される。却下（書き出しは星と線のみ）。
- **地図・年輪・完全抽象のメタファー**：地図はGPSが即時イベント専用で疎なため白地図化する。年輪はイベントの束なり（グラフ構造）を表現できない。完全抽象は「あの日のあの人」の想起価値を失う。夜空・星座を採用。
